# Comentários em Python

## Sintaxe e extração

- `#` comentário. Docstring (`"""..."""` ou `'''...'''`) é string literal que vira `__doc__`, consumida por `help()`, Sphinx, pdoc, mkdocstrings e IDE.
- Docstring de uma linha (`"""Retorna o total em centavos."""`) é one-liner. Docstring multi-linha (Args/Returns/Raises, parágrafos) segue a regra do time: condense em uma linha com o porquê ou remova.
- String solta no meio do código (sem ser a docstring do módulo, classe ou função) funciona como comentário. Trate como comentário.
- Comentário em f-string e string multi-linha de SQL (`"""SELECT ... -- nota"""`) faz parte do dado. Não toque.
- Linhas `#` consecutivas formam um comentário.

## Diretivas a preservar (lista Python)

- Linha 1 e 2: `#!/usr/bin/env python3`, `# -*- coding: utf-8 -*-`, `# vim: ...`.
- Lint e tipos: `# noqa`, `# noqa: E501`, `# type: ignore`, `# type: ignore[code]`, `# pyright: ignore[...]`, `# pyright: basic|strict`, `# mypy: disable-error-code=...`, `# pylint: disable=...`, `# ruff: noqa`, `# flake8: noqa`, `# bandit: nosec`/`# nosec`, `# nosemgrep`, `# isort: skip`, `# isort: off|on`, `# fmt: off|on|skip`, `# yapf: disable`.
- Cobertura: `# pragma: no cover`, `# pragma: no branch`.
- Gerado: `# Generated by`, `# This file was automatically generated`, `# DO NOT EDIT`. Pule o arquivo.
- Alembic: `# revision identifiers, used by Alembic.` e variáveis `revision`/`down_revision` no topo da migration. Preserve o cabeçalho.
- Django: `# noqa` em `from x import *` de settings; comentário `# Generated by Django X on <data>` (gerado, pule).
- Docstring consumida: Sphinx autodoc, pdoc, mkdocstrings (cheque `docs/conf.py`, `mkdocs.yml`, `pyproject` com `pdoc`). FastAPI usa docstring da função de rota como `description` do OpenAPI, e `summary` vem do nome. Mantenha um one-liner nas rotas.
- Doctest: exemplos `>>>` na docstring são testes executáveis (`--doctest-modules`). Preserve o exemplo e condense só o texto.
- Pydantic/FastAPI `Field(description="...")` é código, não comentário.

## Motivo obrigatório em supressões

- `# type: ignore` sem código: handoff para review-tipagem (exigir `# type: ignore[codigo]`). Aqui, adicione o motivo em um one-liner na mesma linha ou na anterior.
- `# noqa` sem código (`# noqa` puro): handoff para o dono da regra silenciada. Aqui, adicione o motivo.
- `# nosec` e `# nosemgrep`: exigem motivo. Sem ele, MAJOR com handoff para review-seguranca.
- `# pragma: no cover` em ramo novo de lógica de negócio: sinal para test-audit.

## Docstring: o que fazer

- Tipos já estão nas anotações: remova `:type x:`, `:rtype:`, `Args: x (int)` com tipo repetido.
- `Args:`/`Returns:`/`Raises:` que repetem nome e anotação: remova.
- `Raises:` quando a exceção é relevante e não evidente: condense em uma linha (`"""Busca a matrícula. Lança MatriculaNaoEncontrada se inativa."""`).
- Docstring de módulo com descrição de várias linhas: condense em uma linha ou mova o texto para README. Preserve a docstring de módulo quando o `__doc__` alimenta CLI (`argparse` com `description=__doc__`, `click`).
- `click`/`typer`: a docstring do comando vira o texto de `--help`. Mantenha uma linha útil ao usuário.
- Docstring vazia (`""" """`) ou só com o nome da função: remova.
- Classe `dataclass`/`pydantic`: docstring de uma linha. Atributos autoexplicativos ficam sem comentário.
- Padrão do repo prevalece: se `ruff` tem `D` (pydocstyle) ligado e exige docstring em função pública, não remova docstring de função pública. Condense para one-liner. Cheque `[tool.ruff.lint] select` e `pydocstyle` no `pyproject.toml`.

## Padrões comuns de ruído em Python

- `# TODO: tipar`, `# FIXME` sem ticket.
- `# imports`, `# constants`, `# helpers`, `# main`: rótulos de seção. Remova (NIT).
- `# Initialize the variable`, `# Loop through the list`, `# Return the result`: repetem o código. Remova.
- `# -----` e `# =====`: banner. Remova.
- `# print(x)`, `# import pdb; pdb.set_trace()`: código comentado. Remova. `breakpoint()` esquecido ativo no diff é achado de outro dono (review-resiliencia/review-seguranca conforme o caso). Reporte como handoff.
- Bloco longo de `# ` explicando algoritmo: mova para docstring de uma linha mais link, ou README.
- Comentário em notebook (`.ipynb`): fora de escopo, salvo célula de código aprovada pelo usuário.

## Padrões de adição de alto valor em stacks Python

- Unidade: `timeout = 30  # segundos`.
- Regex: `# CPF com ou sem pontuação`.
- SQLAlchemy/Alembic: `# server_default evita lock de backfill`, `# Índice parcial: só linhas ativas`.
- Django: `# select_related evita N+1 na listagem`, `# Sem transaction.atomic: o job é idempotente`.
- FastAPI: `# Dependência síncrona roda em threadpool`, `# response_model filtra campos privados`.
- Workaround de lib: `# Workaround: pydantic 2.5 não serializa Decimal em dict aninhado (pydantic#8123)`.
- Ordem e concorrência: `# Ordem importa: commit antes de enfileirar o job`.
- Valor mágico: `PAGE_SIZE = 100  # teto do BFF`.
- Segurança: `# Não logar: contém token do aluno`.

## Falsos positivos frequentes

- `# type: ignore[attr-defined]` com código: preserve.
- `# noqa: E501` em URL longa: preserve.
- Docstring de uma linha em função pública quando o lint exige: preserve.
- `#!/usr/bin/env python3` e coding cookie.
- String com `#` (`"cor: #fff"`, regex com `#`, f-string): não é comentário.
- Cabeçalho de migration Alembic: preserve.
- Exemplos `>>>` executados por doctest.
